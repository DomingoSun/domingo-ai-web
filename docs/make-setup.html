Make 預約自動化設定

有人在 domingoai.com 預約 30 分鐘評估時，Make 會自動建立 Google 日曆會議和 Meet 連結、寄確認信給客戶、請 Claude 寫會前摘要寄給你，再把 Meet 連結寫回網站後台。照這份做一次，大約 40 分鐘。

情境 1 個每筆預約約 6 次操作Make 免費方案 1,000 次／月
  1. 網站客戶送出預約
  2. Google 日曆建立會議＋Meet，邀請客戶
  3. Gmail確認信寄給客戶
  4. Claude寫會前摘要
  5. Gmail摘要寄給你
  6. 網站寫回 Meet 連結，狀態變「已確認」
00

先準備好

  1. Make 帳號：到 make.com 註冊，免費方案就夠用。
  2. Google 帳號：用來開會的日曆，以及寄信的 Gmail。
  3. Anthropic API 金鑰：到 console.anthropic.com → API Keys → Create Key。帳戶要先儲值一點額度。金鑰只貼在 Make 的連線設定裡，不要貼到對話、文件或任何檔案。
  4. 網站已上傳最新外掛：後台「網站設定」底下要看得到「自動化」。
用 @gmail.com 寄信要多一步。Make 規定一般 Gmail 帳號連 Gmail 模組時，要用自己在 Google Cloud 建立的 OAuth 用戶端（約 15 分鐘，做一次就好）。Google 日曆不需要這一步。如果你用的是自己網域的 Google Workspace 信箱，可以直接連。步驟在最下面的「附錄 A」。
01

建立情境，接上網站

  1. Make → Create a new scenario，命名「多明哥｜預約自動化」。
  2. 第一個模組選 Webhooks → Custom webhook → Add → 名稱填 domingo-booking → Save。
  3. 按 Copy address to clipboard 複製網址（長得像 https://hook.us2.make.com/…）。
  4. 到 WordPress 後台 網站設定 → 自動化，貼上網址，按「儲存」。
  5. 回到 Make，Webhook 模組會顯示「正在等待資料」。這時到網站後台按 送出測試資料。
  6. Make 顯示 Successfully determined，代表它已經認得所有欄位，之後就能用點選的方式帶入。
這個網址等同鑰匙，拿到的人就能送假資料進來。不要貼在公開的地方。
02

加上分流（Router）

在 Webhook 後面加 Flow Control → Router，拉出兩條路線，各自在連接線上按扳手圖示設定篩選條件：

路線 A：新預約條件 event → Text operators: Equal to → created
路線 B：取消條件 event Equal to cancelled，再加一條 AND：event_id → Exists

「送出測試資料」的 event 是 test，兩條路線都不會走，不會真的建立會議或寄信。

05

開啟並實測

  1. 右下角排程設為 Immediately as data arrives，把情境開關切到 ON，按 Save。
  2. 用手機到 domingoai.com 做一次真的預約，Email 填你自己的另一個信箱。
  • 收到 Google 日曆邀請，裡面有 Meet 連結
  • 收到「預約成功」確認信，Meet 連結點得開
  • 你的信箱收到「會前摘要」
  • 後台「預約」這筆出現 Meet 連結，狀態是「已確認」
  • 把這筆改成「已取消」：日曆會議消失、收到取消信、預約頁那個時段重新開放
06

出問題時看哪裡

後台「會議」欄顯示「送出失敗，會自動重試」網站送不到 Make。確認情境是 ON、網址沒貼錯。網站會在 5 分鐘、10 分鐘後各重試一次。
Make 有收到，但日曆沒建立打開 Make 的 History 看是哪個模組紅色。最常見的是 Google 連線過期，重新連一次。
Gmail 連線每 7 天就斷Google Cloud 的 OAuth 同意畫面還在「Testing」狀態。到 Google Auth Platform → Audience 按 Publish app 改成正式版（自己用不需要送審）。
後台沒出現 Meet 連結檢查 A5 的 Header 名稱是 X-Domingo-Secret，值是點選 secret，不是手打。
次數快用完每筆預約約 6 次操作。免費方案每月 1,000 次，大約 160 筆預約。
A

附錄 A：@gmail.com 連 Gmail 模組

  1. 到 console.cloud.google.com 建立新專案，名稱例如「Make 寄信」。
  2. APIs & Services → Library，搜尋 Gmail API → Enable。
  3. OAuth consent screen（Google Auth Platform）：類型選 External；應用程式名稱填「Make」；支援信箱和開發者聯絡信箱填你自己；Authorized domains 加 make.com 和 integromat.com。
  4. Scopes 加入 https://mail.google.com/。
  5. Test users 加入你要連的 Gmail 地址（這步沒做會連不上）。
  6. Credentials → Create credentials → OAuth client ID → 類型 Web application；Authorized redirect URIs 加 https://www.integromat.com/oauth/cb/google-restricted。
  7. 建立後會看到 Client ID 和 Client Secret。直接到 Make 的 Gmail 模組 → Add connection → Show advanced settings 貼上，不要存到任何檔案或對話。
  8. 登入 Google 時如果看到「這個應用程式未經驗證」，按「進階」→「前往 Make」→ 允許。
  9. 最後到 Audience 按 Publish app，避免連線 7 天後失效。
Make 的介面偶爾會改名稱或位置。如果找不到某個選項，以 Make 官方說明「Connecting to Google services using a custom OAuth client」為準。
